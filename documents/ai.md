# AI Architecture

**Project Name:** Discipline AI

**Version:** 1.0

**Current Provider:** Google Gemini

**Future Providers:** OpenAI, Claude, OpenRouter, Grok (xAI), Qwen

---

# Overview

Artificial Intelligence is responsible for transforming structured behavioural analytics into natural language coaching.

The AI does not calculate statistics.

The AI does not access the database.

The AI does not generate reports from raw task history.

Instead, it receives a structured behavioural summary generated by the Analytics Engine and produces personalised insights based on that data.

This separation keeps the system deterministic, explainable and cost-efficient.

---

# AI Philosophy

The AI layer follows one simple rule.

> AI should think.
>
> Software should calculate.

Traditional software is responsible for calculations.

Examples

- Completion Rate
- Streaks
- Productivity Score
- Weekly Trends
- Behaviour Score
- Consistency
- Correlation

Artificial Intelligence is responsible for interpretation.

Examples

- Behaviour Analysis
- Coaching
- Recommendations
- Motivation
- Long-term Insights
- Future Suggestions


```json
    "06:00",

  "mostCommonReason": "Phone",
```

# Daily Report

Generated every night.

The AI receives

- Today's completion rate
- Today's completed tasks
- Today's missed tasks
- Today's failure reasons
- Previous daily trends

The AI returns

- Summary
- Biggest achievement
- Biggest weakness
- One recommendation
- Motivation

# Behaviour Analysis

The AI should answer questions such as

- Why is productivity decreasing?

- Which habits influence each other?

- What causes missed tasks?

- Which time period performs best?

- What behaviour changed this month?

- What should improve next?

The AI should never invent reasons.

Every explanation must reference analytics.

---

# Recommendation Rules

Every recommendation must be evidence based.

Bad

```
Sleep more.
```

Good

```
Your afternoon completion rate is 38% lower than your morning completion rate.

Consider moving difficult work before lunch.
```

Bad

```
Go to the gym.
```

Good

```
You completed 91% of your evening study sessions during weeks where you exercised at least four times.
```

Recommendations should always explain WHY.

---

# Hallucination Prevention

The AI must never

- Invent statistics
- Guess behaviour
- Assume emotions
- Create fake trends
- Mention unavailable data

If evidence does not exist,

the AI should explicitly state

"Insufficient data."

---

# Behaviour Memory

The AI should gradually develop context.

One day of data

↓

Very limited understanding.

One week

↓

Early trends.

One month

↓

Reliable patterns.

Six months

↓

Strong behavioural model.

One year

↓

Highly personalised coaching.

Longer history should improve coaching quality.

---

# Prompt Strategy

The backend builds the prompt.

Prompt contains

- Behaviour summary
- User goals
- Historical metrics
- Recent reports
- Current analytics

Prompt never contains

- Raw Firestore documents
- Internal IDs
- Sensitive information
- Large datasets

The backend is responsible for context preparation.

# Context Window Optimisation

Never send unnecessary information.

Instead of

```
200 task records
```

send

```
Completion Rate

Streak

Most skipped habit

Behaviour score

Top failure reasons

Trend changes
```

Smaller prompts reduce

- Cost
- Latency
- Token usage

and improve consistency.

---

# Cost Optimisation

AI is one of the most expensive parts of the system.

The project should minimise unnecessary AI calls.

AI should NOT run

- Every reminder
- Every button click
- Every task completion

AI should run

- Daily reports
- Weekly reports
- Monthly reports
- Manual report regeneration

Analytics should be reused whenever possible.

---

# Error Handling

If the AI provider fails

The system should

- Retry
- Log the failure
- Notify monitoring
- Continue operating

The dashboard should remain usable even if AI is unavailable.

Analytics should always exist.

AI reports are optional enhancements.

---

# Security

Never send

- Firebase IDs
- Authentication tokens
- Internal metadata
- Sensitive credentials

Only behavioural analytics should be shared with the model.

# Summary

The AI layer is not the brain of Discipline AI.

The Analytics Engine is the brain.

The AI is the interpreter.

Its purpose is to transform deterministic behavioural metrics into clear, personalised and actionable coaching.

By separating analytics from reasoning, the system remains reliable, explainable, scalable and cost-efficient while allowing AI providers to evolve without changing the overall architecture.
